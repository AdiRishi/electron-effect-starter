# Server

The Effect HTTP and WebSocket RPC server. The desktop shell and the browser are both clients of it. State ownership, the ticket flow and the session store follow [T3 Code](https://github.com/pingdotgg/t3code)'s server.

- **One server owns a state directory.** At startup the server holds an exclusive SQLite lock on `server-owner.sqlite`. A second server for the same directory exits with code 78, and the desktop shell stops restarting when it sees that code.
- **Dev state is separate.** Behind the Vite dev server, state lives under `dev/` instead of `userdata/`, so a dev run never migrates the real database. A base directory passed with `--base-dir` or `APP_HOME` is used as given.
- **Migrations only append.** The migrator skips every id up to the highest one it has recorded, so never edit, reorder or reuse a released id. The server warns at startup when the recorded history names ids this build does not know.
- **Subscriptions send a snapshot, then live events.** The store stamps each change with a revision while holding a semaphore. A subscriber drops live events at or below its snapshot's revision, so it sees every change exactly once. Wrap the snapshot in `rpcInitialItems`, because `Stream.concat` keeps its first stream alive for the whole subscription. A new stream follows the notes store.
- **Every client ends up with a session.** A session is an HMAC-signed token, valid for 30 days and signed with a secret kept in the state directory, backed by an `auth_sessions` row. A token verifies only while its row is unrevoked, and `SessionStore.revoke` and `revokeAllExcept` revoke rows.
  - Desktop: the shell writes a bootstrap token to the server on fd 3. The token is valid for 24 hours and any number of exchanges. The shell's main process exchanges it at `/oauth/token` for a bearer token and gives that to the renderer over IPC. Each exchange revokes the previous desktop bearer session.
  - Browser: in web mode the server prints a one-time pairing URL (`#token=…`) to stdout, not to the log, because log records also become span events. The token is valid for 5 minutes, or 24 hours behind the Vite dev server. The page trades it at `/api/auth/browser-session` for an HttpOnly cookie, and the new session replaces the browser's previous cookie session.
  - The cookie name is per server instance (`app_session_<port>` on desktop, `app_session_<port>_<state hash>` on loopback), because cookies span ports and two servers on one host would overwrite each other's.
  - Cookie-authenticated requests are accepted only from the server's own origin (`Host` or `X-Forwarded-Host`), the desktop renderer origins, or the Vite dev origin.
  - WebSockets authenticate at the upgrade, with a 5-minute `?wsTicket=` from `/api/auth/websocket-ticket` or with the cookie. The server closes a socket when its session is revoked, replaced or expires.
- **Auth failures are logged.** A rejected session credential logs a warning, a failed auth route logs its endpoint and error tag, and an internal failure logs its cause before the route answers `InternalError`. `--log-websocket-events` (`APP_LOG_WS_EVENTS`) logs every request, and is on by default behind the dev server.
