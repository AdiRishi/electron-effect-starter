# Desktop shell

The Electron main process, built from Effect layers. It supervises the server and hosts the web build. Most of it is ported from [T3 Code](https://github.com/pingdotgg/t3code)'s desktop app; when you change ported code, compare with t3code before inventing a different design.

- **Each build owns its userData.** Development uses `<productName> (Dev)`, so its state, Chromium profile and single-instance lock never touch the installed app's. `DesktopUserData.layer` sets userData and takes the instance lock before any layer that writes into it; a second launch quits there.
- **The server runs as a child process.** The backend manager starts the bundled server with Electron's own binary (`ELECTRON_RUN_AS_NODE=1`). It writes the bootstrap envelope, including the bootstrap token, to fd 3, so the token never appears in argv or the environment. It waits for an HTTP readiness probe, restarts the server after an unexpected exit with a backoff of 500 ms doubling to 10 s, and stops restarting on exit code 78.
- **Quitting waits for the server.** `before-quit` is held while the main window's bounds are saved, windows are destroyed and the server stops. Process signals take the same path, and a repeated quit after 10 seconds exits anyway. The updater's own quit is let through, so installing an update stops the server first, then calls `quitAndInstall`.
- **Logs rotate.** `desktop.log` and `server.log` in `<userData>/logs` rotate at 10 MB and keep ten files. A server run that fails writes its last 1 MiB of output to `server-child.log`. Development also echoes server output to the terminal.
- **The renderer is locked down.** It loads from a custom scheme (`electron-effect-starter://app`, or the `-dev` scheme, which proxies Vite) that serves a strict CSP. It runs sandboxed and may only write to the clipboard and go fullscreen. It reaches the main process only through the preload bridge, and each IPC method decodes its arguments and encodes its result with a schema from `@app/contracts`.
- **Electron is reached through services.** `ElectronApp`, `ElectronWindow`, `ElectronMenu`, `ElectronScreen`, `ElectronShell`, `ElectronTheme`, `ElectronDialog` and `ElectronUpdater` wrap the Electron APIs, and tests replace them with fakes from `tests/support`. Module mocking is banned, so new Electron calls go behind one of these services or an injected function.
- **Verify a shell change** with `pnpm build`, `pnpm --filter @app/desktop smoke-test` and `pnpm --filter @app/desktop verify:preload`, as well as `pnpm check` and `pnpm test`.
